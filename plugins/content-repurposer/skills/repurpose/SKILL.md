# 内容多平台改写

你现在要把用户提供的原始内容（一篇文章、一段视频文案、一个想法或大纲）改写成多个社交媒体平台的**原生风格**版本，而不是简单地缩短或翻译。每个平台的读者习惯、算法偏好、格式规范都不同，必须分别处理。

## 工作流程

1. **确认原始内容**：如果用户消息里没有直接粘贴内容（只给了一个文件路径或 URL），先读取/询问，拿到完整原文再开始。不要凑合着用标题猜测内容。
2. **确认目标平台**：
   - 如果 `$ARGUMENTS` 或 `platforms` 参数里指定了平台，只做指定的。
   - 如果没指定，默认做全部 5 个平台：小红书、Twitter/X 线程、公众号图文、短视频口播稿、知乎回答。
   - 平台名称支持中英混用识别（如"小红书"/"xiaohongshu"/"rednote"、"推特"/"twitter"/"x"）。
3. **提炼核心信息**：先在心里（不用输出）提炼原文的：核心论点、3-5 个可复用的信息点/案例、一句话钩子（hook）、目标读者可能的疑问。所有平台版本都应该忠于原文事实，不能编造数据或案例。
4. **逐平台改写**：对每个目标平台，阅读对应的 `references/` 风格指南后再生成内容。不要用同一套文案简单地加/减字数敷衍不同平台——语气、结构、开头钩子必须换掉。
5. **输出格式**：用平台名称作为二级标题分隔每个版本，方便用户直接复制。每个版本末尾附一行字数/条数统计。

## 平台风格指南（按需读取）

生成对应平台内容前，先读取该平台的详细指南：

- 小红书笔记 → `references/xiaohongshu.md`
- Twitter/X 线程 → `references/twitter_thread.md`
- 公众号图文 → `references/wechat_article.md`
- 短视频口播稿（抖音/视频号/YouTube Shorts） → `references/video_script.md`
- 知乎回答 → `references/zhihu.md`

## 重要原则

- **忠实原文**：不虚构数据、引用、案例。如果原文信息不够支撑某平台要求的篇幅或结构（例如知乎需要论证，但原文只是一条感想），如实告知用户信息不足，而不是编造填充。
- **不做违规诱导**：不生成诱导私信打款、虚假中奖、医疗保健功效担保等违反各平台社区规范的话术。
- **保留可选的品牌/CTA位**：如果用户提供了个人简介、产品名、转化链接等信息，在合适的位置（如小红书正文末尾、公众号文末、视频口播结尾）自然植入一次，不要每个平台都硬广。
- **一次交付所有请求平台**，不要每次只做一个平台等用户催。
